# Relay's tiny behavior Transformer

Relay uses an original, trained causal Transformer to score 35 behavior choices
and five attention targets. It is a behavior policy, not a language model or
a conscious animal. Ordinary application code still handles needs, routines,
physical eligibility, animation, interaction, and persistent personal memories.

The model has two pre-normalized attention blocks, width 96, six heads per
block, feed-forward width 192, tanh-approximation GELU, and a maximum context of
32 observations. Each observation retains the established 22 normalized inputs.
The trained parameters are fixed during use: remembering interactions changes
local context and preferences; it does not retrain neural weights.

There are 155,848 trained float32 parameters and 3,072 fixed positional values:
635,680 numeric bytes in total. C# performs inference locally without Python,
PyTorch, model downloads, external services, voice output, or generated words.
The policy runs at a nominal five decisions per second while active;
interactions can request an immediate refresh. Rendering has its own clock.

## Data and provenance

All examples and soft labels are generated by this repository's original
synthetic teacher. No external training corpus, videos, real-cat recordings,
user tracking data, cursor recordings, or pretrained weights are used.
Behavior choices are design interpretations of familiar household-cat activity,
not a veterinary or scientific model of feline cognition. See
[the behavior notes](RELAY-BEHAVIOR.md) for the research informing the design.

The committed recipe trains on 8,000 independent episodes of 12–32 steps from
22 scenario families. They cover quiet observation, predatory play and pauses,
repetition and habituation, gentle contact, rapid pestering and retreat,
sudden versus gradual novelty, post-play grooming, settling and waking,
surface exploration, solitary play, social choice, calm handling, release,
and compound events. Four recall families deliberately converge on identical
current observations after different earlier events. Their privileged teacher
memory is absent from the model's inputs, so the model must use token history.

Training, progress validation, final held-out evaluation, and unseen ordered
event mixtures use separate seeds. The 1,200 held-out episodes reuse scenario
families with new initial states, noise, duration and cue timing. An additional 600 episodes use
four event orderings excluded from training. Exact counts and measured metrics
are recorded in [RELAY-TRAINING.json](RELAY-TRAINING.json).

Evaluation also compares matched histories with identical final observations,
repeated final frames, and shuffled earlier frames. This measures whether
history and order affect the policy. Agreement and probability differences
measure imitation of the synthetic design teacher, not intelligence, emotions,
real-cat fidelity, or consciousness.

## Measured comparison

Both frozen models were audited on the same fresh examples. On the ordinary
held-out split, behavior agreement improved from 91.27% for the 19,208-parameter
baseline to 97.41% for this model. Attention agreement was 99.02% and 99.46%.
On the unseen ordered mixtures, behavior agreement was 79.99% and 85.21%,
and attention agreement was 90.96% and 95.06%. These are results from one
training seed per architecture, not a statistical guarantee that a larger
model is always better. The JSON report retains both models' distribution
errors, checkpoint details and hashes. These results measure the synthetic
teacher's design preferences; they do not measure a real cat's behavior.

## Reproduction

Use Python 3.13 with the CPU-only development dependencies in
`tools/requirements-kitty-training.txt`. Install the PyTorch wheel using its CPU
index. From the source root run:

```powershell
python tools/train_kitty_policy.py --episodes 8000 --validation-episodes 1200 --epochs 90 --batch-size 96 --threads 4 --work-dir work/relay-transformer-training
```

The seed is 20261101. Training uses CPU autograd, AdamW, gradient clipping and a
cosine learning-rate schedule. Checkpoint selection uses the lowest behavior
KL plus 0.6 times attention KL on the progress-validation split. The final
audit sets do not select a checkpoint. The JSON report includes dependency versions,
training duration, validation metrics and progress checkpoints. Runtime timing
is measured independently in the C# tests.

The script generates `KittyModel.cs`, the JSON report, and 12 golden probability
vectors in `tests/Kitty.Tests/transformer-golden.json`. Golden cases include
history pairs, cold starts, the full context boundary and a sequence longer
than the context. C# numerical parity, causality and bounded history are tested
separately. Floating-point behavior can vary slightly across library versions
and platforms; the golden probability tolerance is 0.0001.

Original model weights, teacher, synthetic recipe and fixtures use the project's
Apache 2.0 license. PyTorch and NumPy are development dependencies and are not
part of the distributed application.
